# Habit 重构 PRD

## 文档信息

- 产品：Deadliner
- 功能：Habit 习惯系统重构
- 版本：PRD v0.1
- 状态：待评审
- 日期：2026-08-18
- 目标平台：iOS、Android、HarmonyOS、Widget/Watch 等既有扩展入口
- 依赖规格：`spec.md`

## 1. 背景

KMP 已将 Habit 从 Task/DDL 中拆成独立聚合，但产品行为仍沿用旧模型：`DAILY/WEEKLY/MONTHLY` 同时承担重复日期和目标统计周期，无法表达“仅工作日执行”；提醒也只能表达一个时间，无法稳定跟随计划日。艾宾浩斯已有明确价值，需要在重构中完整保留。

本次不以兼容旧 UI 结构为目标，而是重新定义 Habit 的用户心智：

> Habit 是一个在特定日期出现、按明确方式记录进度、可在统计窗口内达成目标的长期行为。

## 2. 产品目标

1. 用户能创建“每天”“工作日”“周末”或自定义周几重复的习惯。
2. 习惯提醒只在计划日出现，完成、归档、删除或改计划后不残留错误提醒。
3. 用户能选择一键打卡或累计数量，直接表达“工作日每天背 20 个单词”。
4. 保留按周、按月和累计总目标，但不再把周期目标伪装成每天都欠一次。
5. 完整保留经典艾宾浩斯复习曲线、非复习日阻断和下一次复习提示。
6. 三端、搜索、Widget/Watch 和 AI 创建入口使用同一套规则。
7. 老用户升级后，历史记录、累计进度和艾宾浩斯锚点可解释、可验证。

## 3. 非目标

- 不为 Task/DDL 增加重复能力。
- 不支持任意 cron、隔 N 天、法定节假日自动排除、地理位置或一天多个提醒。
- 不实现 SM-2、自适应间隔、答题评分或知识卡片系统。
- 不重做连续天数、成就、排行榜和社交功能。
- 不要求重构 Android `AddDDLActivity`；该页面只承担最小接线，不再新增 Habit 领域规则。

## 4. 产品原则

### 4.1 计划与目标分离

- 计划回答“哪天可以做”。
- 目标回答“在哪个统计窗口完成多少”。
- 提醒从计划派生，不再保存另一份可能漂移的星期集合。

### 4.2 非计划日不制造负担

- 普通习惯在非计划日不出现在“今日待完成”列表，不进入当天完成率，也不可打卡。
- 历史日历仍可查看已有记录，但不能补写到原本非计划的日期。

### 4.3 周期目标不污染每日完成率

- 每计划日目标进入每日完成率。
- 每周、每月、累计目标进入独立的“周期进度”区域，不进入每日完成率分母。

### 4.4 艾宾浩斯保持可预期

- 首版只提供经典曲线，不根据完成质量自动改变间隔。
- 重启曲线是显式动作，普通编辑不能偷偷改变锚点。

## 5. 核心概念

| 概念 | 用户含义 | 示例 |
| --- | --- | --- |
| 计划日 | 习惯允许出现和记录的日期 | 周一至周五 |
| 追踪方式 | 用户如何记录完成 | 一键打卡、累计数量 |
| 目标窗口 | 进度何时清零或累计 | 每计划日、每周、每月、累计 |
| 目标值 | 窗口内需要达到的数量 | 1 次、20 个、3 次 |
| 提醒 | 计划日内的一个本地时间 | 工作日 08:30 |
| 艾宾浩斯计划 | 由锚点与经典偏移生成的复习日 | 第 0/1/2/4/7/15/30/60 天 |

## 6. 用户场景

### 6.1 工作日数量习惯

用户创建“背单词”：

- 重复：工作日。
- 追踪：累计数量。
- 每计划日目标：20。
- 单位：个单词。
- 默认增加量：1，可手动输入本次完成数量。
- 提醒：08:30。

周一至周五显示 `0/20 个单词`，周末不进入待完成列表且不提醒。

### 6.2 自定义周几打卡

用户创建“力量训练”，选择周一、周三、周五，一键打卡。只有这三天进入当日完成率。

### 6.3 灵活周目标

用户创建“每周跑步 3 次”，计划日选择每天、目标窗口选择每周、目标值为 3。它显示在“本周目标”中；本周达到 3 次后完成，后续计划日不再提醒。

### 6.4 艾宾浩斯复习

用户创建“复习英语四级词汇”，系统按经典曲线生成复习日。复习日可打卡且可提醒；非复习日在“下一次复习”区域显示倒计时，不进入当日完成率，也不能打卡。

## 7. 功能需求

### 7.1 创建与编辑

编辑器按以下顺序组织：

1. 名称与描述。
2. 习惯类型：常规习惯 / 艾宾浩斯。
3. 重复计划。
4. 追踪与目标。
5. 分类、颜色、图标等既有属性。
6. 提醒。

常规习惯的重复计划提供：

- 每天。
- 工作日。
- 周末。
- 自定义：周一至周日至少选择一天。

常规习惯的追踪方式提供：

- 一键打卡：目标值固定为 1，不显示数量输入。
- 累计数量：目标值为正整数，可填写不超过 12 个字符的单位和正整数默认增加量。

目标窗口提供：

- 每计划日。
- 每周。
- 每月。
- 累计。

提醒区域显示最终摘要，例如“周一至周五 08:30 提醒”或“仅在艾宾浩斯复习日 21:00 提醒”。

### 7.2 今日列表

- “今日待完成”只包含今天是计划日且尚未完成日目标的常规习惯。
- 已完成日目标的习惯保留在列表中并显示完成状态，避免完成后突然消失。
- 周/月/累计目标放在独立的周期进度区域，展示当前窗口进度和剩余量。
- 非计划日的普通习惯不显示。
- 艾宾浩斯复习日显示在今日列表；非复习日显示在“下一次复习”区域。

### 7.3 日期浏览

- 选择历史日期时，按该日期当时的计划规则展示应做项与记录。
- 未来日期只可预览，不可打卡。
- 修改计划后，首版按最新计划解释所有日期是否为计划日；历史记录始终保留并单独可见。
- 如果需要“计划规则历史版本”，作为后续能力，不在本轮实现。

### 7.4 打卡与数量记录

一键打卡支持：

- 完成。
- 撤销当天完成。

累计数量支持：

- 增加默认数量。
- 输入本次完成数量。
- 将当天进度直接设为目标值。
- 清空当天进度。

规则：

- 数量必须为正整数；设置为 0 等价于清空。
- 达到目标后仍保留超额数量，但完成率上限按 100% 展示，详情可见真实值。
- 非计划日、未来日期、已归档 Habit 不接受新增记录。

### 7.5 每日完成率

- 分母：当天处于计划日的 `每计划日` 目标数量。
- 分子：其中已达到目标值的 Habit 数量。
- 周/月/累计目标不参与每日完成率。
- 艾宾浩斯仅在复习日参与每日完成率。
- 当天没有任何日目标时，显示“今天没有安排”，不显示 0% 失败状态。

### 7.6 周期进度

- 每周以 ISO 周一为起点。
- 每月以本地日历自然月为窗口。
- 累计目标从 Habit `startOn` 起持续累计。
- 周/月目标在窗口完成后保持完成状态，下一窗口自动从 0 开始。
- 周/月目标只允许在选中的计划日记录；非计划日不可为了追赶目标而补记。

### 7.7 艾宾浩斯

- 经典偏移：`0, 1, 2, 4, 7, 15, 30, 60` 天。
- 第 0 天为 `startOn`。
- 每个复习日是一键打卡目标 1。
- 非复习日显示：还有 N 天开始 / 还有 N 天复习 / 已完成记忆周期。
- 第 60 天完成后进入“周期已完成”，不会自动重启。
- 用户可以显式选择“重新开始记忆周期”，新锚点默认为当天；历史记录不删除。
- 归档、恢复、删除行为沿用普通 Habit。

### 7.8 提醒

- 每个 Habit 首版最多一个提醒时间。
- 提醒只在计划日产生。
- 日目标达到后取消当天尚未触发的提醒。
- 周/月/累计目标达到后取消当前窗口内后续提醒。
- 艾宾浩斯只在复习日且尚未完成时提醒。
- 修改时间、计划、目标、归档状态或同步覆盖后立即重建。
- 设备重启、应用升级、系统时间或时区变化后重建。
- 权限被拒绝不影响 Habit 保存；UI 显示提醒未生效并提供系统设置入口。

### 7.9 搜索、Widget 与 Watch

- 搜索结果显示今天的 due 状态、进度与下一次计划提示。
- Widget/Watch 在非计划日禁用打卡，不得绕过领域规则写记录。
- 数量习惯的 Widget 默认动作是增加默认数量；打开 App 可输入自定义数量。
- 艾宾浩斯非复习日显示下一次复习提示。

### 7.10 AI/LiFi 创建

AI 需要识别：

- “每天”“工作日”“周末”“每周一三五”。
- “每天 20 个单词”“每周 3 次”“累计 100 次”。
- 提醒时间。
- “用艾宾浩斯复习”。

创建前确认卡必须展示计划日、追踪方式、目标窗口、目标值/单位与提醒，禁止仅展示模糊的 `DAILY/WEEKLY`。

| 每计划日目标 | 是 | 否 | 待完成 | 是 | 是 | 是 |

## 9. 旧数据升级体验

- DAILY：迁移为每天 + 每计划日目标。
- WEEKLY：迁移为每天可记录 + 每周目标，保留本周累计行为。
- MONTHLY：迁移为每天可记录 + 每月目标。
- TOTAL：目标窗口迁移为累计。
- EBBINGHAUS：保留经典曲线，以旧 `createdAt` 对应的迁移锚点继续计算。
- ONCE：只作为历史兼容类型迁移为单次计划；新编辑器不提供新建入口。
- 所有历史 `HabitRecord` 保留，不因为新计划日规则删除。
- 升级后首次进入 Habit 页无需用户逐条确认；无法确定的异常记录进入诊断日志，不阻塞其他 Habit。

## 10. 权限与付费

- 通知权限只控制提醒是否投递，不限制 Habit 本身。
- 艾宾浩斯继续作为 Pro 创建能力，三端使用同一 entitlement 判断。
- 已存在的艾宾浩斯 Habit 即使当前无 Pro，也允许查看、打卡、归档和导出；“新建”和“重新开始曲线”需要 Pro。

## 11. 数据与指标

首版建议记录不含用户内容的本地/匿名产品事件：

- Habit 创建成功率与失败原因。
- 计划预设使用分布：每天/工作日/周末/自定义。
- 追踪方式分布：打卡/数量。
- 提醒授权与实际成功规划数量。
- 升级迁移成功、降级和异常数量。
- 艾宾浩斯复习日完成率。

## 12. 验收标准

1. “工作日每天背 20 个单词，08:30 提醒”可从编辑器和 AI 两条路径正确创建。
2. 周六、周日不显示上述 Habit、不计入完成率、不可从搜索/Widget 打卡且无提醒。
3. 周一记录 12、再记录 8 后显示 20/20；超额记录保留真实值。
4. 每周 3 次目标只出现在周期进度区，不导致一周被计算为 7 个未完成日目标。
5. 艾宾浩斯第 0/1/2/4/7/15/30/60 天可打卡并可提醒，其他日期只能看到倒计时。
6. 修改周几或提醒时间后，三端系统中不存在旧计划残留提醒。
7. Android Receiver、BootReceiver、Widget，iOS App/Widget/Watch，HarmonyOS Reminder 与页面均遵循 shared due 状态。
8. 旧 DAILY/WEEKLY/MONTHLY/TOTAL/EBBINGHAUS 数据升级后进度与历史记录可见。

## 13. 发布策略

- 先在 KMP 完成领域规则、迁移和同步协议，再接三端 UI，避免多端产生不同新数据。
- 新 Snapshot 协议上线前，旧客户端保持只读兼容或阻止向已升级数据集写入，具体由 TRD 定义。
- 使用内部迁移样本与真实匿名备份副本做灰度验证。
- 三端完成同一验收样本后再开放 AI 创建新合同。
