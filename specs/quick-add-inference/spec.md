# 快速添加端侧推理适配

## 背景
现有规则解析易误判。原生推理后端、在线模型与实时提案已接入；本轮修复截图中的时间空格和习惯语义误判。

## 目标
KMP 统一推理生命周期、命名张量契约、错误处理；通过 expect/actual 接入 Android ONNX Runtime、HarmonyOS 系统 MindSpore Lite、iOS 系统 Core ML。

## 非目标
不修改数据库、传统添加业务或 AI 接口。独立真实语料准确率评测、量化、运行时算子裁剪和三端真机性能优化留 TODO；不能以合成集或 host 推理代替这些验收。

## 用户场景
打开快速添加即可输入；模型下载过程可见，准备完成后尝试本地识别。模型就绪后的语义拒绝保持待确认草案，可手动 AI 或展开编辑；只有模型不可用才走保守规则，提案显示真实识别来源。

## 验收标准
三端实际调用原生推理 API，支持 INT32/INT64/FLOAT32 输入、FLOAT32 输出（Core ML 额外支持 FLOAT16/DOUBLE 转 FLOAT32）；检查名称、shape、类型和数据长度；后台串行加载/推理/释放；异常可传回 Swift；重载失败保留旧模型；关闭可重复调用。macOS 测试后端显式不可用。
编译三端共享代码并验证原生链接；共享契约及生命周期测试通过。无模型时不宣称识别精度/性能达标。

## 风险与约束
无 breaking change，不修改数据库；文件低于 1000 有效行。Core ML 不支持 INT64 输入，以无损 INT32 转换承接 token ID，并要求导出模型输入为 INT32；模型输入 shape 首版固定，拒绝静默 resize。鸿蒙按官方要求先销毁 model 再 context；先使用 CPU 基线，NNRt 调优留 TODO。

## 2026-10-10 补充：v3 预训练分词

清单可选 codec.wordPiece 与旧字符清单兼容。KMP 完成 WordPiece、单字符规范化、Unicode 偏移和 token BIO 到字符投影；三端推理 API 与张量名称/形状保持一致。iOS Core ML 使用 CPU 浮点路径，避免半精度改变接受判断。有效留出集输入逐条与上游 BERT tokenizer 对照，三格式输出还需在生产 KMP 中生成完全相同的提案。

v3 构造冻结集中文完整正确覆盖85.28%、英文92.00%，两组0错误接受；差距6.72个百分点仍未达训练工程预设<=5点目标，预发布不等于正式验收通过。训练、失败轮次、数据分区与三格式证据见同级 DeadlinerQuickAddTraining/docs/pretrained-v3-delivery.md。

## 2026-10-10 补充：压包与在线模型
Android 默认内置 ONNX Runtime，并可用 quickAddInferenceAbis 指定 ABI、分别构建；quickAddInferenceRuntime=false 仅为规则诊断构建。缺少运行时返回不可用，不能因类缺失崩溃。JNI 类及成员必须保留，避免 R8 删除原生调用的构造方法。
共享层提供 HTTPS 单文件流式下载、声明大小/SHA-256 校验、内容寻址缓存和同目录原子替换；后台准备与输入预览分离。下载、校验、编译或加载失败时使用规则解析，取消保持取消语义；缓存有效时可离线加载。Android/鸿蒙下载 ONNX/.ms；iOS 下载单文件 .mlmodel 后由 Core ML 编译；.mlpackage/多文件 ONNX 外部权重留 TODO。
没有模型 URL、权重、词表和标签时不自动联网，不启用语义识别。新增公共识别门面允许后续 codec 接入，并对模型不可用或失败使用 QuickAddParser；UI 仍不等待下载。构建并分析实际小包，保留原签名 APK，生成独立未签名验证包。

## 继续交付：下载模型自动识别
Android 默认内置 ONNX Runtime，通过 ABI splits 产出独立 APK，显式通用包开关仍保留；不能把缺少引擎视为完成压包。三端在首次打开快速添加时读取随包 quick-add-model.json，后台准备配置指定的平台权重；模型 READY 后自动刷新当前输入。清单缺失或无平台权重不联网，规则仍可使用。清单包含 schemaVersion、modelId、平台 artifact 的 URL/大小/SHA-256，以及字符词表、固定长度和置信度阈值。
首版明确采用 Unicode 字符级 BIO 槽位模型，INT32 input_ids/attention_mask [1,L]；intent_logits [1,3] TASK/HABIT/OTHER，slot_logits [1,L,9] 标注标题、时间、周期、备注。严格输出 shape/BIO/概率门限，不截断长输入，未知字符率超限则回退。时间和周期仍由规则归一化，无法归一化也回退。该契约已有实际从零训练的模型、三格式权重和发布清单。
三端输入先显示规则提案，再异步尝试模型；必须丢弃旧输入结果，并防止模型覆盖用户手改字段、AI 结果、保存或已展开页面。共享层提供配置/解码/会话，平台只处理资源路径和 UI 生命周期。无真实模型时明确记录端到端验收待办，不制造成功或精度数据。

## 用户补充：下载必须可见
三端快速添加界面展示检查缓存、下载百分比、加载中、就绪、失败/暂停与规则降级；失败提供重试。不得后台静默下载而 UI 无提示。当前尚无模型清单时显示“模型尚未配置，当前使用规则识别”，不假装下载成功。

## 模型实际交付授权
用户要求由本任务选择并交付可验收模型，并指定使用项目 GitHub Releases 托管。选择小型字符卷积联合意图/槽位模型，从可复现的合成中文样本训练首版，发布前导出 ONNX/Core ML/MindSpore 并做真实数值和提案验收。合成样本不能代表真实准确率；独立人工样例与失败例必须公开，保守门限和规则/AI 回退保持。权重独立发布至公共 DeadlinerStudio/DeadlinerCore Release，不上传私有业务数据、凭据或现有闭源源码。

## 本轮修复：习惯语义与空格（2026-10-10）

截图回归：`每天下午 3 点交报告书` 应生成 HABIT、标题交报告书、DAILY、15:00 提醒。时间解析支持 ASCII/全角空格位于时段、小时、点/冒号和分钟之间，保持非法时刻拒绝。新版合成训练采用任务/习惯共用标题池，加入时间空格增强，禁止动作词库决定意图。发布新不可变模型版本，三端更新清单；提案显示 MODEL/LOCAL/AI 的真实来源，模型 READY 仍仅代表加载。验收使用真实三格式输出验证 kind、title、reminderTime 并公开失败/拒绝；不宣称独立真实语料准确率。
