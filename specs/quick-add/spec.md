# 快速添加

## 背景
传统表单需要逐字段输入。三端提供一个输入框，随输入实时展示单个任务或习惯提案。

## 目标
- 平台各自持久化 `quick_add_enabled`（初始关闭）；设置页可切换。
- KMP 同步解析常用中文/英文日期、时间与习惯周期，无法可靠解析时复用单任务/习惯 AI 提取。
- 提案不自动写入；用户确认一次保存，或展开为保留提案的传统表单。
- 本地提案立即更新；AI 等输入停顿 450ms 后请求，取消/版本检查阻止过期覆盖。

## 非目标
批量添加、复杂 UI 设计、偏好跨设备同步。

## 用户场景
输入“明天下午3点交报告”立刻出现任务及截止时间；输入“每周一三五跑步”立刻出现习惯及执行日；复杂表达进入 AI 识别并显示状态与失败信息。

## 验收标准
- 开关重启保持；关闭时传统添加行为保持。
- 清空输入清空提案并禁用保存；无名称、无可靠结果、AI 请求中不可保存。
- 快速输入、清空、展开、关闭后旧 AI 结果不得覆盖当前表单。
- 一次确认只创建一个条目；AI 返回多个条目要求展开修正。
- 日期解析依据用户时区，覆盖跨月跨年、星期、下午/晚上和无时间默认日末。
- 展开后名称、截止时间、执行日、次数保留。

## 风险与约束
客户端位于独立 Android/iOS/HarmonyOS 仓库，二进制需同步部署才可使用新增 API。增量接口，无数据库迁移；不提交已有未提交工作。统一完成实现后构建验证；新核心文件不超过 1000 有效行。

## 实现边界
本地规则覆盖常用中文日期/时刻、中文数字、ISO 日期与基本英文日期/周期；不认识的调度表达请求 AI。纯标题任务不生成虚构截止时间。AI 若返回多条、无效日期或当前简易编辑器不能完整表达的高级习惯日程/计量单位，禁止直接确认，并提示展开处理。iOS 沿用现有 AI 开关与会员限制；偏好不跨端同步。展开后的传统任务表单沿用已有必填截止时间的默认值。

## Android 快速添加反馈修正（2026-10-09）
非空输入无法生成本地草案时必须 needsAI=true，包含纯日期/时刻、未识别的相对语义日程；纯任务标题仍然无需 AI，空输入仍然不可触发 AI。Android 采用显式闪光按钮触发请求，不修改其他平台的请求时机。

## 纯数字输入反馈
本地标题必须包含文字；纯数字/符号（如 123）返回 ready=false、needsAI=true。保留带数字的文字标题与纯文字标题本地识别。Android 四属性横行、默认时间与编辑资格由 UI 状态模块管理，DTO 不变；新增回归验证。

## Android AI HTTP 错误反馈
Android KtorLlmClient 启用 expectSuccess，将非成功 HTTP 响应作为带状态码的异常抛出，避免鉴权失败被误报为 JSON 解析失败。Android 快速添加映射状态码与安全提示，不展示响应正文或凭据。API/DTO 不变，不改其他平台实现。
