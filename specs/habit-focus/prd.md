# 习惯绑定专注 PRD

日期：2026-10-12。状态：Core / Android 已实现；联合打卡、数量输入与 Android 双向滑动入口已由用户确认。

## 产品定义

习惯专注回答「为这个习惯投入了多久」，打卡回答「计划目标完成了多少」。两者独立，用户可选择一次操作共同记录，不靠计时推断完成量。

## 已确认

- 有「结束专注」和「结束并打卡」两条路径。
- 数量型习惯需填写本次实际完成数量，增加现有进度；不自动按默认数量增加，也不一键补齐目标。
- Android 习惯行复用类似 Task 的左右滑操作：右滑「归档、专注」，左滑「编辑、删除」，替代常驻计时图标方案。

## 首版规则

- ACTIVE 且未删除的习惯可启动。非计划日允许显式专注，但联合打卡不可用；已完成目标仍可专注。
- 正计时、暂停、恢复、提前结束、时长更正/删除和本设备单计时规则沿用现有专注。
- 倒计时到点只保存专注，不触发打卡或自动弹出数量输入。
- 一键打卡型联合结束只确认完成：已完成则不修改原记录，绝不撤销。周/月/累计目标沿用其实际进度规则，不能把一次打卡解释为整窗目标达成。
- 数量型确认页显示归属日、单位和本次输入，背景计时页保留习惯名；现有进度由 Core 校验，不在弹层堆叠统计文字。允许取消，取消不结束计时、不写打卡。计时在输入时继续按原规则推进，避免暗中多出暂停。
- 数量输入期间若倒计时到点，先保存专注；过期的联合命令不得对新的活动会话生效。可在该已保存会话的结果路径显式补做打卡，须具有持久化幂等关联，不能重复增加。
- 专注时间继续按会话开始的本地日期统计。联合打卡默认归属启动时日期；跨午夜确认时明确显示该日期，不偷偷切成次日。实现需保存日期上下文，避免时区变化重算。
- 计划、目标或单位在计时中被编辑，结束时重新校验；若数量弹层打开后元数据变更，提交拒绝并提示关闭后重新确认，不沿用已失效的数量含义。
- 归档/删除需显式解决当前计时；跨端发生失效时收尾保存已有有效时长，禁止继续，不打卡、不丢历史。
- 删除/更正专注不联动撤销打卡，两条记录可独立更正。

## Android 入口与排版

- 右滑指手指向右、卡片向右位移，露出左侧「归档、专注」两个按钮；左滑露出右侧「编辑、删除」两个按钮。按钮按上述次序从左至右排列，不额外加入 Task 的完成/放弃操作。
- 保留原习惯卡片布局，不增加常驻计时图标；习惯行点击仍打卡，长按仍进入多选。操作区已展开时点击卡片只收起，不误打卡；多选时收起并禁用左右滑。
- 复用 Task 的手势识别、展开/收起动画、按钮视觉、触感与单行展开控制；习惯两侧都只有两个动作，不能套用 Task 三动作一侧的展开宽度。
- 「专注」点击后收起操作区，打开已绑定该 Habit 的现有专注设置面板。若已有活动计时，走现有计时解决流程，不自动结束旧会话或改绑。
- 归档/删除遇到当前习惯正在计时，先显式解决计时，不能直接使目标失效。编辑保留原编辑入口，计时结束时重新校验计划和目标。
- 删除点击必须进入确认，不直接移除；若沿用 Task 的全滑快捷行为，左全滑也只唤起删除确认，右全滑对应归档，不自动触发专注。
- 同一主列表/宿主最多展开一个 Task 或 Habit 操作区，切换页签、日期和进入多选时收起。现代与经典习惯行都遵循此规则。
- 为 TalkBack 提供等价的具名自定义操作，避免将四个动作仅藏在手势里；沿用 Task 可用触控尺寸和主题色，不新增页面 chrome。
- 现有专注设置中的目标选择扩展为同一列表内的任务/习惯分组，避免再叠一个 Tab。全局选择可找到非计划日的活动习惯。
- 复用现有设置面板、计时页、只在活动计时存在时显示的浮动栏及后台通知。
- 计时页显示目标名与短类型标识；Habit 用「结束并打卡」，Task 保留「结束并完成」。数量输入仅在用户选择联合结束时出现。
- 习惯时间摘要用短行呈现，不给每个习惯新增一整套大型统计卡片。

## 统计建议

- 原「总览 / 趋势 / 上月」中的专注时间合计两类目标，任务成果/完成率口径不变。
- 时间投入排行用短类型标识区分任务、习惯，分类按各目标当前分类解释；删除目标时显示历史名称快照。
- 同时保留按单个习惯、按类型查询的 Core 能力；首版不为此增加二级筛选导航。

## 后续可讨论

按时长达标的习惯是一项独立追踪方式，不属于本次「绑定计时」扩展。跨日打卡日期手工选择、单个习惯的专门历史入口样式留后续；首版固定启动日，计时页沿用按当前目标查看历史的能力。
