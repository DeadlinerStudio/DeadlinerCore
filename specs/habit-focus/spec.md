# 习惯绑定专注

## 背景

2026-10-11 用户提出为习惯绑定现有专注计时，并明确首版同时支持「结束并打卡」；数量型习惯先输入本次实际完成数量，再增加进度。
用户随后确认 Android 入口采用习惯行双向滑动：右滑归档/专注，左滑编辑/删除，不使用常驻计时图标。
实现前运行代码仅支持 Task。现已扩展 Core 与 Android，Habit 使用独立的类型化目标，未创建伪 Task。

## 目标

- 共享同一个正计时/单轮倒计时，每次会话只能绑定一个 Task 或 Habit；本设备仍最多一个活动计时。
- 习惯提供「结束专注」「结束并打卡」，保存有效秒数；倒计时自然结束只保存专注，不自动打卡。
- 数量型联合操作由用户填写正整数实际完成量；一键打卡型确认完成，不调用会撤销完成的 toggle。
- 延续当前简洁 UI：原有三页签、卡片和图表库不变，不增加 Task/Habit 二级 Tab。
- 先落地 KMP 与 Android，并为其他客户端保留明确的升级与桥接合同。

## 非目标

- 不将时长转为次数/数量，不增加「累计 30 分钟即完成」追踪方式。
- 不修改习惯计划、目标、艾宾浩斯曲线或原打卡入口行为。
- 不增加并行计时、无目标计时、中途改绑、自动循环或跨设备活动计时接管。
- 不把习惯伪装成 Task，不把习惯数累计到任务完成数中。

## 用户场景

1. 阅读习惯启动 25 分钟倒计时，提前结束只记录实际时间，也可选择结束并完成当天打卡。
2. 背单词习惯专注结束，填写本次完成 12 个，记录专注并将当天进度增加 12，而非填写计时分钟数。
3. 非计划日主动为习惯专注，记录时间但不新增打卡；已完成目标仍可计时。
4. 从任务切换到习惯前必须解决现有计时，不能生成第二个活动会话。

## 验收标准

- Task/Habit 目标身份以类型和 UID 共同定义；相同 UID 不串历史、统计、通知和操作。
- 用户已确认：支持结束并打卡、数量型输入实际完成量、Android 双向滑动入口；其余首版默认规则按 prd.md 落地。
- 普通结束/倒计时到点不改变 HabitRecord；打卡也不凭空生成专注会话。
- 联合操作原子保存 FocusSession、合法 HabitRecord 与变更日志，清除活动计时；失败不可留下半成功结果。
- 重复联合命令不重复增量，不撤销一键打卡，不操作后续新会话。
- 联合打卡遵守现有计划日、未来日、有效习惯与数量校验。校验失败保留可恢复计时并可改选仅结束。
- 活动习惯已打卡不阻止继续；归档/删除后的目标不可启动或恢复。历史会话仍保留名称快照。
- 更正/删除专注只影响时间，不自动撤销原打卡；撤销打卡也不删除专注。
- 统计总专注可包含两类目标，任务成果图仍仅包含 Task；分布能辨认目标类型，不显示误导的任务数。
- 已有 Task 数据、活动会话、同步/备份和桥接需要兼容测试；旧客户端不应静默损坏习惯会话。
- Android 验证两类入口、后台恢复、联合操作/取消数量输入、空态、深浅色和大字体。
- Android 习惯卡右滑仅展示归档/专注、左滑仅展示编辑/删除；现代/经典样式保留原卡片，不复制 Task 完成/放弃语义。操作按钮不触发打卡，展开时点击先收起、多选时禁用滑动，删除需确认。

## 风险与约束

- 同步 JSON 严格解码。Snapshot/changelog 升为格式 6 且强制输出版本字段；新客户端迁移旧 Task 格式，旧客户端必须拒绝新格式。混合版本不能视为可持续互写，其他客户端需升级 Core 后参与同步。尚未用实际旧 APK 做混合设备验收。
- 工作区有大量其他未提交修改；实施前已用临时 index 和独立本地 Git 备份引用保存完整工作状态，未切换分支、修改真实暂存区或推送。不得直接回退整个工作区覆盖其他工作。
- 非计划日计时是本轮推荐沿用此前暂定规则，不放开 HabitRecord 的 NOT_DUE 限制。
- 保持每个核心文件小于 1000 有效行，先按职责拆分再统一编译。

## 当前状态

Core 与 Android 已实现。数据库 schema 8 / 增量迁移 7.sqm；联合写入由 SQL 事务和持久化会话标记保证原子性与幂等。Android 保留现代/经典习惯行、原三个统计页签及项目图表库。
iOS 状态桥接与 OHOS Kotlin C API 已提供新命令并编译验证，但两端原生 UI 入口尚未实现，不列入 Android 首版验收。具体测试、截图与限制见 acceptance.md。
