## 目标

- 支持与一个 Active Task 强绑定的正计时与单轮倒计时，并排除暂停时间。
- 支持“结束专注”和原子化的“结束并完成 Task”。
- 可靠恢复应用后台、进程终止与设备重启前的本机活动计时。
- 按 Task 聚合总时长，并保留可核查、可更正的会话历史。
- 在 KMP shared 中统一计时状态机、Task 状态协作、持久化、聚合与同步合同。
- 首发提供今日摘要、Task 累计和最近会话，复杂分析后置。

## 非目标

- 首版不支持 Habit 计时，不预埋 `targetType` 多态合同。
- 首版不提供完整番茄工作法循环、自动休息、白噪音或网站拦截。
- 首版不支持未绑定 Task 的自由计时，也不支持一个会话绑定多个 Task。
- 首版不保证跨设备实时接管同一个活动计时。
- 首版不支持手工补录一条从未计时的会话。
- 首版不提供复杂周/月趋势、Task/Category 分布或效率洞察。

## 用户场景

1. 用户从一个 Active Task 启动 25 分钟倒计时，暂停 5 分钟后继续；最终只记录实际专注时间。
2. 用户点击“结束专注”，会话被保存而 Task 保持 Active。
3. 用户点击“结束并完成”，会话保存与 Task `COMPLETED` 在同一业务操作中完成。
4. 用户从 Task 列表完成正在计时的 Task，系统要求确认并将结束计时与完成 Task 组合处理。
5. App 在正计时期间被系统终止；再次打开时能恢复同一个活动计时。
6. Task 删除后，既有历史仍可通过标题快照阅读，但不能发起新计时。

## 验收标准

- 未选择 Task 或 Task 非 Active 时，UI 与底层命令都拒绝启动/继续。
- 同一设备同一时刻最多有一个活动计时。
- 正计时、倒计时、暂停、继续、结束、结束并完成、丢弃和到点行为符合 `prd.md` 状态表。
- 提前结束倒计时记录实际时长；自然到点记录计划时长。
- “结束并完成”不会产生 Task/会话只成功一半的状态。
- 其他 Task action 入口不能绕过活动计时；需先确认解决。
- 完成会话、向下更正或删除后，Task 总时长立即正确重算。
- 活动计时在进程重启后恢复；离线到点后按计划终点幂等落为完成会话。
- 已完成会话可通过 Snapshot、WebDAV/ChangeLog、DeadlinerServer 与备份恢复；活动计时不跨设备同步。
- 首发可读取今日总时长、Task 今日/累计时长和最近会话。
- 三端对同一组领域用例得出一致结果。

## 风险与约束

- `focus_session` 是独立聚合，只引用 `taskUid`；Task 删除不级联历史，引用完整性由 repository 校验。
- `TaskRepository` 已返回“存在活动计时时先解决”的结果；平台 Task 状态入口仍需展示确认流程并调用组合解决命令。
- 运行期间优先使用单调时钟；跨进程恢复使用 UTC 墙上时钟，需要处理时间回拨与前跳。
- 后台通知不是完成记录的唯一事实来源；恢复时必须重新计算并幂等收敛。
- Snapshot 合同已从 v4 升级为 v5，并为旧版本提供空 `focusSessions` 迁移路径。
- `trd.md` 第 20 节技术决策已关闭并进入实现。
- Core 第二批不宣称三端可用；完整验收需等 bridge、生命周期和三端展示接入完成。
