# Task Focus Timer PRD

## 文档信息

- 产品：Deadliner
- 功能：Task 专注计时与总时长
- 版本：PRD v0.2
- 状态：已实现（Task-only MVP，待发布前真机 QA）
- 初稿日期：2026-09-01
- 更新日期：2026-09-10
- 目标平台：Android、iOS、HarmonyOS
- 依赖规格：`spec.md`

## 1. 一句话定义

用户可以为一个具体 Task 启动正计时或单轮倒计时；结束后的有效专注时长进入该 Task 的历史和总时长，任何计时都不能脱离 Task 独立存在。

## 2. 本轮范围决策

首发只支持 Task，不支持 Habit。

原因：Habit 的合理入口和产品语义尚未确定。Habit 计时可能是“投入时间记录”，也可能应该成为新的“按时长完成”追踪方式；在没有验证前直接复用 Task 计时，容易与计划日、打卡和目标进度产生冲突。

本轮不在 UI、领域合同、数据库或同步协议中预埋 Habit 分支。Habit 是否需要计时将作为独立产品探索，见第 16 节。

## 3. 背景与问题

Deadliner 已能回答一个 Task 是否完成，但不能回答：

- 这项 Task 实际投入了多久？
- 今天的专注时间花在了哪些 Task 上？
- 完成一项 Task 前经历了几次专注？

普通番茄钟常产生无归属的时间记录，之后难以统计。本功能将“计时”和 Task 强绑定，让每一段专注时间都可追溯到具体工作。

## 4. 产品目标

1. 从 Task 上下文中，以不超过两步启动计时。
2. 同时支持不设上限的正计时和有目标时长的单轮倒计时。
3. 暂停、后台、进程被终止和设备重启后，已投入时间仍可解释、可恢复。
4. 在 Task 详情展示累计总时长与可核查的会话历史。
5. 用户可选择“结束专注”或“结束并完成”，明确控制 Task 是否进入 `COMPLETED`。

## 5. 非目标

- 首版不支持 Habit 计时。
- 不提供未绑定 Task 的自由计时。
- 不在一个会话中切分或绑定多个 Task，也不允许计时中途改绑。
- 不实现自动循环的工作/休息番茄序列、长休息规则、白噪音、专注锁机或应用屏蔽。
- 不按预计工时自动排程，不实现计费、工时审批或团队 timesheet。
- 首版不支持手工补录一条从未计时的会话，也不支持跨设备实时接管活动计时。
- 首版不提供复杂周/月趋势图、分类分布或效率洞察。

## 6. 产品原则

### 6.1 先有 Task，再有计时

- 启动命令必须携带一个有效的 `Task.uid`。
- 全局计时入口必须先选择 Task；Task 详情入口自动绑定当前 Task。
- Task 在计时期间不可被静默替换。若要切换，先结束或丢弃当前会话。

### 6.2 专注结束与 Task 完成由用户明确选择

- “结束专注”：记录本次时长，Task 保持 `ACTIVE`。
- “结束并完成”：记录本次时长，并在同一业务操作中将 Task 标记为 `COMPLETED`。
- 倒计时自然到点只结束专注，不自动完成 Task；完成页可继续执行“完成任务”。
- 删除或更正专注会话不反向撤销 Task 的完成状态。

### 6.3 已完成 Task 不能继续计时

- 只有 `ACTIVE` Task 可以启动或继续活动计时。
- 若用户从其他入口完成当前正在计时的 Task，必须先确认“结束当前计时并完成任务”；确认后两个动作一起完成，取消则两个动作都不发生。
- 若同步使当前 Task 变为非 Active，本机在感知后立即停止并保存已发生时长，不允许继续或恢复。

### 6.4 总时长可追溯

- 总时长是所有未删除完成会话的 `durationSeconds` 之和，不在 Task 表中保存可漂移的缓存字段。
- 每个会话保留 Task UID 与标题快照；Task 改名后默认显示新标题，Task 删除后使用快照降级展示。

### 6.5 后台提醒不是真相来源

- 系统通知用于告诉用户倒计时已到，不负责定义会话是否完成。
- App 恢复时根据持久化锚点收敛到唯一结果，避免重复记时或漏记。

## 7. 核心概念

| 概念 | 含义 |
| --- | --- |
| 绑定 Task | 每次计时唯一归属的 Active Task |
| 活动计时 | 当前设备上尚未完成或丢弃的计时，可为运行中或已暂停 |
| 专注会话 | 已完成并计入统计的一段有效时间 |
| 正计时 | 从 0 开始累计，直到用户结束 |
| 单轮倒计时 | 从预设时长递减；有效时长达到计划值时自动结束专注 |
| 有效时长 | 所有运行片段之和，不包含暂停时间 |
| Task 总时长 | 该 Task 所有未删除专注会话有效时长之和 |

## 8. MVP 功能范围

### 8.1 入口与 Task 选择

- Task 详情和 Task 快捷菜单显示“开始专注”。
- 全局专注入口先展示最近专注 Task、今日 Active Task，并支持搜索 Active Task。
- 从 Task 上下文进入时直接绑定该 Task；从全局入口进入时必须先选 Task。
- 不允许“稍后再绑定”或创建临时文本目标。

Task 可用性：

| Task 状态 | 可启动 | 可继续 | 历史 |
| --- | --- | --- | --- |
| `ACTIVE` | 是 | 是 | 可查看 |
| `COMPLETED` | 否 | 否 | 保留、可查看 |
| `ARCHIVED` | 否 | 否 | 保留、可查看 |
| `ABANDONED/ABANDONED_ARCHIVED` | 否 | 否 | 保留、可查看 |
| 已软删除 | 否 | 否 | 以标题快照保留 |

### 8.2 计时模式

启动前选择：

- 正计时：默认选项，无计划结束时间。
- 倒计时：快捷值 15、25、45、60 分钟，并允许 1–180 分钟的自定义整数。

首版没有自动休息。倒计时结束后停止累计超时时间，但 Task 仍保持 Active。

### 8.3 时钟页操作

运行中：

- 暂停。
- 结束专注。
- 结束并完成。
- 丢弃。

已暂停：

- 继续。
- 结束专注。
- 结束并完成。
- 丢弃。

操作语义：

- “结束专注”：生成会话，清空活动计时，Task 状态不变。
- “结束并完成”：生成会话，清空活动计时，Task 标记为 `COMPLETED`；整个操作必须原子化，不能只成功一半。
- “丢弃”：不生成会话，不改变 Task；必须二次确认。
- 有效时长为 0 时不能结束，只能继续或丢弃。
- 同一设备全局最多一个活动计时；启动另一个 Task 前必须处理当前计时。

### 8.4 从其他入口完成 Task

- 若完成的不是当前计时绑定 Task，按现有流程处理。
- 若完成的是当前计时绑定 Task，显示确认：“该任务正在计时，是否结束计时并完成任务？”
- 确认后等价于时钟页“结束并完成”；取消后 Task 与计时均不变化。
- 归档、放弃或删除当前计时 Task 也必须先确认结束计时；确认后记录已发生时长，再执行目标状态变更。

### 8.5 时长规则

- 精度为秒；UI 运行时显示到秒，列表可按场景显示到分钟。
- 暂停时间不计入有效时长。
- 完成会话的有效时长至少为 1 秒。
- 倒计时提前结束记录实际有效时长，不补齐计划值。
- 倒计时自然到点记录恰好为计划值的时长。
- 正计时不会自动封顶；超过 12 小时时显示“计时是否仍在进行”的显著提示，但不自动丢弃。

### 8.6 后台、强杀与重启

- 运行中切到后台后继续按实际时间推进。
- 暂停后切到后台不增长。
- App 被系统终止或设备重启后，重新打开仍恢复同一个活动计时。
- 倒计时在 App 不运行时到点：系统尽力通知；下次打开时自动补落完成会话，结束时间使用计划到点时间。
- 若系统时间异常变化导致不可解释的负时长，不增加时长，并提示用户检查/处理会话。

### 8.7 完成后的反馈

普通“结束专注”和倒计时到点后的完成页展示：

- 本次有效时长。
- 绑定 Task。
- 该 Task 更新后的总时长。
- Task 仍为 Active 时显示“完成任务”按钮。

“结束并完成”后的完成页明确显示 Task 已完成，不再重复展示完成按钮。

### 8.8 历史与更正

- Task 详情显示总时长、今日时长以及最近专注会话。
- 用户可向下更正一条完成会话的有效时长，范围为 1 秒至 `min(24 小时, 会话始末跨度)`；不改变原始开始/结束时间。
- 用户可删除错误会话；删除后总时长立即重算。删除是可同步的软删除。
- 首版不能新增一条没有真实计时过程的历史会话，也不能修改绑定 Task。
- 今日统计按会话 `startedAt` 对应的本地日期归属；跨午夜会话首版不拆分到两个自然日，Task 累计总时长不受影响。

### 8.9 多设备行为

- 已完成专注会话参与同步和备份。
- 活动计时只在启动它的设备恢复，不参与同步。
- 两台设备可以分别为同一 Task 计时；完成后两条会话都保留并累计。
- 同一会话 UID 的修改/删除按现有 LWW 规则解决冲突。

## 9. 状态与操作矩阵

| 当前状态 | 暂停 | 继续 | 结束专注 | 结束并完成 | 丢弃 | 到点 |
| --- | --- | --- | --- | --- | --- | --- |
| 无活动计时 | — | — | — | — | — | — |
| 正计时 `RUNNING` | → `PAUSED` | — | 会话 + Task 保持 Active | 会话 + Task Completed | 清空 | — |
| 正计时 `PAUSED` | — | → `RUNNING` | 会话 + Task 保持 Active | 会话 + Task Completed | 清空 | — |
| 倒计时 `RUNNING` | → `PAUSED` | — | 实际时长 + Task 保持 Active | 实际时长 + Task Completed | 清空 | 计划时长 + Task 保持 Active |
| 倒计时 `PAUSED` | — | → `RUNNING` | 实际时长 + Task 保持 Active | 实际时长 + Task Completed | 清空 | 不推进 |

所有命令必须幂等：重复点击结束、重复处理到点或生命周期重复回调都不能生成第二条会话或重复转换 Task 状态。

## 10. 展示与信息层级

### 10.1 Task 列表与详情

- Task 行可选择性显示紧凑总时长，例如 `2h 35m`；首发默认只在详情显示，避免主列表信息过载。
- 正在计时的 Task 在列表显示活动指示。
- Task 详情显示“开始专注”、今日时长、总时长和最近会话。

### 10.2 全局迷你计时条

- App 内主页面显示当前 Task、运行/暂停状态和时间。
- 点击进入全屏时钟；提供单击暂停/继续。

### 10.3 全屏时钟

- Task 名称是主要上下文，时间是主要视觉信息。
- 倒计时展示计划时长与剩余时长；正计时展示已用时。
- “结束专注”和“结束并完成”必须有清晰层级；丢弃远离主操作且二次确认。

## 11. 统计分期

### 11.1 首发轻量统计

- 全局专注页：今日总时长、今日会话数、最近会话。
- Task 详情：今日时长、累计总时长、最近会话。
- 完成页：本次时长与该 Task 新总时长。

首发不要求独立分析页；全局专注入口同时承载轻量摘要和开始计时。

### 11.2 下一阶段分析

- 本周/本月总时长与每日趋势。
- 按 Task、Category 的时间分布和排序。
- 自定义日期范围与历史筛选。
- Task 完成前的专注次数、平均单次时长。
- 是否增加“预计时间 vs 实际时间”，需另行设计 Task 预计时长字段。
- 统计阶段只消费 FocusSession，不改变计时与 Task 完成规则。

## 12. 通知与权限

- 倒计时启动或继续时安排一次到点通知；暂停、结束、丢弃时取消。
- 正计时不安排到点通知；超过 12 小时的提醒属于应用内恢复提示，首版不保证后台通知。
- 通知权限被拒绝不阻止计时，但启动倒计时时明确提示“到点可能无系统提醒”。
- 通知点击打开对应活动计时或已完成会话。

## 13. 指标与隐私

建议只记录不含 Task 标题或备注的产品事件：

- 启动成功/失败与失败原因。
- 正计时/倒计时选择及预设分布。
- 结束专注、结束并完成、自动到点、丢弃、恢复、编辑、删除数量。
- 通知权限与调度结果。
- 会话时长区间，不记录用户内容。

专注历史属于用户业务数据，纳入导出、备份、删除和同步边界；不得写入明文诊断日志。

## 14. 验收样例

1. 未选 Task 无法开始，底层返回 `TASK_REQUIRED`。
2. 非 Active Task 不能开始或继续计时。
3. 25 分钟倒计时运行 10 分钟、暂停 5 分钟、继续 15 分钟后自动结束，记录 1500 秒，Task 仍为 Active。
4. 倒计时提前 12 分钟结束，记录 720 秒而非计划时长。
5. 正计时运行 10 分钟、暂停 5 分钟、继续 20 分钟，“结束专注”后记录 1800 秒，Task 仍为 Active。
6. 相同过程点击“结束并完成”，会话记录与 Task `COMPLETED` 在同一业务操作中成功；任一失败都不得留下半完成状态。
7. 从 Task 列表完成正在计时的 Task 时必须确认；确认后结束计时并完成 Task，取消后两者都不变化。
8. 强杀 App 10 分钟后重开，运行中正计时增加约 600 秒，暂停态不增加。
9. 后台到点回调执行两次，最终仍只有一个会话。
10. 编辑会话 1800→1200 秒后总时长减少 600 秒；删除后贡献归零。
11. 删除 Task 后，历史仍显示标题快照，但不能再次启动计时。
12. 两台设备分别完成 10 分钟与 20 分钟，同步后 Task 总时长为 30 分钟。

## 15. 已确认决策

1. MVP 只支持 Task；Habit 暂不进入功能范围。
2. 会话允许在真实始末跨度内向下更正，不允许改绑 Task。
3. 倒计时提前结束记录实际有效时长。
4. Task 完成后不允许继续活动计时；时钟页提供“结束并完成”。
5. 首发只做今日、Task 累计和最近会话等轻量统计；完整分析放入下一阶段。

## 16. Habit 后续产品探索

在决定是否支持 Habit 前，需要先验证：

1. 用户需要的是“Habit 的专注投入历史”，还是“以分钟为单位完成 Habit”。
2. 入口应位于 Habit 行、详情页，还是数量记录面板。
3. 计时时长是否应自动形成 HabitRecord；若是，如何映射 `duration → count`。
4. 非计划日是否允许计时，以及是否影响每日完成率和周期目标。
5. 艾宾浩斯等算法计划是否应该支持计时。
6. Habit 时间统计应累计到 Habit 本身，还是只进入全局专注统计。

推荐在 Task 版本上线后，根据入口点击、会话完成率和用户反馈决定是否立项。若立项，单独建立 Habit Focus PRD/TRD，不直接把 Task 规则复制过去。

## 17. 发布策略

- 第一批先完成 KMP 合同、数据库、计时状态机、恢复和同步，使用测试宿主验证。
- 第二批接一端内部版本验证后台、强杀和“结束并完成”，再接另外两端。
- Snapshot/Server 新合同与三端读写能力同批灰度，旧客户端对新格式明确拒绝或提示升级。
- 首发隐藏在 feature flag 后；验证数据一致性后再默认开启。
