# 原生专注页面与 Android 设计统一

## 背景

两端已具备专注行为，但设置/计时混在表单中，不符合 Android 的集中式计时界面。此次只调整 iOS 与鸿蒙展示和入口，不写 Android 或 Core 业务逻辑。

2026-10-12 后续鸿蒙实测修正规格见 [focus-harmony-repair](../focus-harmony-repair/spec.md)：原生Sheet关闭按钮恢复，miniBar统一水平单行，动态区域拆Component并补材质作用域。下文为上一轮设计及验收历史，不覆盖新的修正规格。

## 目标

- 启动专注仅由 Task/Habit 列表右滑悬停的专注按钮进入；移除首页顶栏专注按钮和详情启动卡。
- iOS Task右滑保留原有全滑行为：非多选模式下全滑执行首项完成；活动任务按钮顺序为完成、专注、放弃，专注只通过悬停后点击触发。已完成/已放弃的撤销、恢复、归档行为不变，Habit不启用全滑。
- 保留活动会话全局栏、通知、目标变更冲突的回到当前计时入口；这些不提供独立新建入口。
- 设置：绑定目标、正/倒计时分段选择、时间预览、15/25/45/60分钟、折叠的自定义1～180分钟、单个开始按钮。
- 计时：居中目标名称、圆形进度盘、有效/剩余时间、状态；结束/暂停继续/联合完成三圆形按钮，摘要与最近五条历史置后。
- 完成后呈现本轮结果，不把设置表单再次塞回计时页；数量确认、历史更正与删除保留。
- 两端新专注页面顶栏只保留标题，不添加动作；关闭/放弃置于内容区。iOS原生Liquid Glass，鸿蒙复用项目原生系统材质兼容层，低版本安全回退。

## 非目标

不改 Android、统计看板、KMP规则/桥接/schema、通知合同、原生全局栏结构；不重构其它列表操作或状态管理。

## 用户场景

右滑任务/习惯，点专注，选择模式与时长，进入计时；退出页面后通过全局栏返回，结束后查看摘要及历史。

## 验收标准

无首页顶栏/详情启动入口；两类目标均可右滑悬停打开预绑定设置；布局顺序与Android一致、开始/暂停/联合完成可用、历史功能不退化；两端构建后记录实际范围和设备限制。

## 风险与约束

多仓库有用户改动，逐块保留；纯展示增量无breaking change，不提交整个工作区。新增组件拆分、1000有效行限制；完整批次后编译。鸿蒙显式DEVECO_HOME；Android禁止构建部署。
